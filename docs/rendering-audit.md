# Проверка лишнего рендера, 18.11.2026

Исправление лишних копирований опубликовано через [Actions 44371318656](https://github.com/maxeliseyev/endlessdrawing-backend/actions/runs/44371318656): frontend `79d1846`, backend `85df206` (backend code прежний, отличие от `5ac7ddf` только в документации).

По запросу владельца проверены повторное построение геометрии, idle, копирование GPU-тайлов и полностью перекрытые штрихи. Локально, Chromium/Firefox/WebKit, DPR 1/2; это не измерения физического iPad, энергопотребления или GPU time.

## Найдено и исправлено: старые масштабы под готовым видом

WebGL при каждом кадре копировал пригодные тайлы прежних масштабов, затем закрывал их непрозрачными тайлами текущего масштаба. На прогретом виде нижние копии не меняли ни одного пикселя. Canvas 2D уже пропускал такой fallback.

Теперь WebGL проверяет готовность всех видимых тайлов текущего масштаба. Если они готовы, fallback не копируется и не удерживается как использованный в текущем кадре. Пока хотя бы один тайл отсутствует или dirty, прежнее резервное покрытие сохраняется.

Контрольная сцена: 240 штрихов четырёх кистей, по 24 точки; вид 1000×700, масштабы 1 → 0.8 → 0.6 → 0.9, затем 60 малых перемещений. Медиана экранных GPU draw calls на кадр:

| Браузер | DPR 1, до → после | DPR 2, до → после |
| --- | --- | --- |
| Chromium | 24 → 4 | 28 → 16 |
| Firefox | 24 → 4 | 28 → 16 |
| WebKit | 24 → 4 | 28 → 16 |

[Счётчики и RGBA hashes](performance/render-cache-audit.json). Конечные пиксели совпали во всех шести парах. В Chromium/DPR 2 начальные кадры плотного сценария дополнительно включали достройку тайлов; её нельзя считать повторной отрисовкой полностью прогретого вида. CPU p50/p95 на этом корпусе находятся около разрешения браузерных часов и не доказывают ускорение FPS. Подтверждено именно устранение лишних GPU-команд и копирований.

Регрессия `tests/e2e/render-cache.spec.ts` сравнивает число копий после истории масштабирования со свежим renderer на том же масштабе. До исправления Chromium давал 24 вместо 4 и 28 вместо 16. После исправления шесть проверок в трёх браузерах прошли: одинаковые пиксели, ноль повторных STATIC_DRAW uploads и offscreen draw calls при прогретом pan, ноль кадров в покое. Отдельно принудительно исчерпывается бюджет построения тайлов: старый масштаб продолжает закрывать недостающие участки.

```sh
npx playwright test tests/e2e/render-cache.spec.ts
```

## Подтверждено: полностью перекрытые штрихи участвуют в построении тайла

`renderTile` выбирает все штрихи с пересекающимися bounds, `drawStrokeList` отправляет их по seq. Проверки полной невидимости за более новыми непрозрачными штрихами нет. Это относится к первому построению и последующей пересборке тайла; готовый кеш не повторяет эти stroke draw calls на каждом кадре.

Контроль: 200 непрозрачных round-штрихов ширины 16, точки `[-50, 0] → [50, 0]`; последний непрозрачный round-штрих ширины 64, точки `[-80, 0] → [80, 0]`. Последний полностью закрывает нижние, включая их сглаженные края. Сравнение с одним верхним штрихом, во всех трёх браузерах и обоих DPR:

- Только верхний: **8 offscreen GPU draw calls**, **3 STATIC_DRAW uploads** при подготовке.
- Верхний плюс 200 закрытых: **1608 offscreen GPU draw calls**, **403 STATIC_DRAW uploads**.
- Конечные RGBA совпадают. На повторном кадре готового вида в обоих случаях **0 offscreen stroke draw calls**.

Один STATIC_DRAW upload относится к служебному quad; остальные — буферы штрихов. Число вызовов не является коэффициентом замедления GPU или FPS. [Результаты](performance/occlusion-audit.json).

Воспроизведение без backend и без изменений публичного мира:

```sh
npm run dev
# В другом терминале; Playwright browsers должны быть установлены:
npm run bench:occlusion -- --strokes 200 --output /private/tmp/occlusion-audit.json
```

Скрипт принимает только локальный Vite origin, создаёт синтетические сцены в памяти, считает реальные WebGL-вызовы и проверяет RGBA. Существующий output не перезаписывается.

## Что остаётся

Исключение полностью перекрытой геометрии — отдельная оптимизация построения тайлов, ещё не реализованная. Пересечения bounding boxes недостаточно: внутри могут быть пустоты, spray, сглаживание и прозрачность. Сохранённая геометрия также нужна после удаления верхнего штриха. Нужны доказуемо непрозрачное покрытие, сохранение seq/opacity и сравнение пикселей на частичном перекрытии, удалении и всех кистях.

Другой кандидат из чтения кода: `syncOverlays` при изменении preview заново готовит и упаковывает весь список pending + preview; неизменяемые pending можно исследовать отдельно. Его стоимость в этом аудите не измерялась.
