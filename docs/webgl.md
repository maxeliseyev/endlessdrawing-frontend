# WebGL-бэкенд рендера

Статус: **публичный холст рисует WebGL2**, если браузер его создаёт. Иначе — прежний Canvas 2D с тайлами. Принудительно: `?renderer=canvas2d`. Admin остаётся на Canvas 2D. Потерянный контекст восстанавливается на том же холсте (тип контекста у холста один); буферы собираются заново из сцены.

Геометрия штриха строится один раз (`src/webgl/tessellate.ts`) и лежит в своём буфере. Подтверждённые штрихи растеризованы в тайлы-текстуры: кадр их копирует. Pan/zoom меняют только то, какие тайлы видны, и uniform камеры у оверлеев. Абсолютные координаты — пара float32 (hi/lo), иначе на `WORLD_LIMIT = 1e9` float32 ошибается на десятки единиц. Круги (round caps/joins и spray) — квад с SDF, не веер треугольников.

## База

- `src/webgl/stroke.ts` готовит один штрих: локальная тесселяция, origin парой float32, цвет. Это происходит на `added` и не зависит от камеры.
- `src/webgl/batch.ts` упаковывает вершины одного штриха (`packMesh`). Общая таблица штрихов и spans остаются чистыми помощниками и покрыты unit-тестами; рендерер ими кадр не собирает.
- `src/webgl/tile-plan.ts` решает, какие тайлы нужны кадру. Правила те же, что у `src/tiles.ts`.

## Шаги

1. Сделано: в тайл попадают только штрихи, чей экстент его пересекает; кадр копирует тайлы вида.
2. Сделано: на `added` буфер этого штриха загружается один раз. Новый верхний штрих дорисовывается в затронутые тайлы. `removed` и вставка не сверху портят только эти тайлы. Остальные не пересобираются.
3. Не сделано: замерить время кадра и память вершин на реальных iPhone/iPad. E2E сравнивает центры штрихов побайтно; края сглаживания могут отличаться от Canvas 2D.
4. Сделано: кеш тайлов в текстурах — это и есть кадр. См. ниже.

## Что уже готово

- `src/scene-renderer.ts` — интерфейс `SceneRenderer`: `resize`, `invalidate`, `dispose` и события `added`/`removed` отрисовываемого множества (`SceneListener` из `scene.ts`). `main.ts` знает только его. Камера, viewport и оверлеи (pending + preview) запрашиваются через `FrameInput` в момент кадра.
- `createSceneRenderer()` — единственная точка выбора бэкенда: WebGL2, иначе `Canvas2DSceneRenderer`.
- Hit-test ластика работает на отдельном 2D-контексте (`createHitContext`), а не на экранном холсте: у холста может быть только один тип контекста. Хит-тест остаётся аналитическим/Canvas 2D и не зависит от GPU.
- Сцена отдаёт ровно одно `added`/`removed` на каждое изменение (confirmed ∪ staging без hidden), штрихи неизменяемы (frozen points) — GPU-буферы можно строить один раз на штрих и освобождать по `removed`.
- Геометрия эффектов уже чистая и детерминированная: `chiselPolygons`, `sprayParticles` (`src/brush-geometry.ts`).

## Как устроено

1. **Тесселяция** (`src/webgl/tessellate.ts`, unit-тесты): round — прямоугольники сегментов и диск радиуса `width/2` в каждой вершине (это round cap и round join); square — прямоугольники, квадратные концы и bevel-треугольник внешнего угла; точка — круг или квадрат; chisel — веер уже выпуклых полигонов; spray — инстансы `(x, y, r)`.
2. **Прозрачность один раз на штрих.** Непрозрачный штрих при полной перерисовке тайла рисуется с depth `LEQUAL`: второй фрагмент того же штриха не затемняет пересечение. Полупрозрачный сначала рисуется в FBO покрытия как непрозрачный и один раз композитится со своей opacity. Дорисовка нового штриха в готовый тайл идёт тем же путём покрытия, чтобы не опираться на устаревший depth буфер тайла.
3. **Порядок по seq.** Полная перерисовка тайла идёт по seq. Поверх тайлов каждый кадр — pending и preview, по snapped-камере, ближе подтверждённых.
4. **Тайлы, а не перерисовка мира.** Непрозрачные тайлы 512×512 backing px, привязанные к миру, по масштабу zoom×DPR. Во время зума — ступени √2, через 180 мс точный масштаб. Кадр копирует готовые тайлы целыми пикселями. Новый верхний штрих (seq больше всех в тайле и очередь короче 256) дорисовывается в затронутые тайлы; удаление или более старая вставка перерисовывает только их. Сдвиг камеры не пересобирает уже видимые тайлы. Новые тайлы — ближние первыми, бюджет ~6 мс/кадр; недостающие закрываются растянутым ближайшим масштабом; в покое — prefetch одного кольца. LRU держит не меньше 48 тайлов. Шейдер штриха ссылается на sampler: на время рисования в FBO на этот unit привязана отдельная текстура 1×1, иначе выборка своей цели отбрасывает проход и тайл остаётся белым.
5. **Отказ.** Нет WebGL2 — Canvas 2D со своим кешем тайлов. Не выделился FBO тайла — прямой проход только видимых штрихов, буфер штриха по-прежнему один. `webglcontextlost` ждёт `restored` и собирает буферы и тайлы заново. Флаг `?renderer=canvas2d` не пишется в Storage. Замер кадра и памяти на iPhone/iPad не сделан.

## Не делать

- Не переносить в WebGL хит-тест/ownership-логику и не смешивать GPU-код с `scene.ts`/`world.ts`.
- Не менять алгоритм spray/chisel (версионирование — `docs/brushes.md`): GPU-рендер обязан воспроизводить ту же геометрию.
