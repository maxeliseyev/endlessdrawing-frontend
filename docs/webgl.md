# WebGL-бэкенд рендера: подготовка и план

Статус: **граница подготовлена, WebGL не реализован.** Публичный холст рисует Canvas 2D с кешем тайлов (`src/tiles.ts`). На mock-сцене из 4000 перекрывающихся штрихов этого достаточно для 60 fps. WebGL нужен, когда сцены вырастут на порядок или перерисовка тайлов (зум, удаления в плотной зоне) станет узким местом на iPhone/iPad.

## Что уже готово

- `src/scene-renderer.ts` — интерфейс `SceneRenderer`: `resize`, `invalidate`, `dispose` и события `added`/`removed` отрисовываемого множества (`SceneListener` из `scene.ts`). `main.ts` знает только его. Камера, viewport и оверлеи (pending + preview) запрашиваются через `FrameInput` в момент кадра.
- `createSceneRenderer()` — единственная точка выбора бэкенда: сейчас всегда `Canvas2DSceneRenderer`.
- Hit-test ластика работает на отдельном 2D-контексте (`createHitContext`), а не на экранном холсте: у холста может быть только один тип контекста. Хит-тест остаётся аналитическим/Canvas 2D и не зависит от GPU.
- Сцена отдаёт ровно одно `added`/`removed` на каждое изменение (confirmed ∪ staging без hidden), штрихи неизменяемы (frozen points) — GPU-буферы можно строить один раз на штрих и освобождать по `removed`.
- Геометрия эффектов уже чистая и детерминированная: `chiselPolygons`, `sprayParticles` (`src/brush-geometry.ts`).

## Что нужно сделать

1. **Тесселяция (чистый модуль, unit-тесты):** round/square-линии → треугольники (полосы с joins: round — веер, bevel для square; caps round/square), точка → круг/квадрат, chisel → полигоны (триангуляция ear-clipping или они уже выпуклые по сегменту), spray → инстансы кругов (`x, y, r`), круги — в фрагментном шейдере по SDF с AA. Координаты относительно первой точки штриха + uniform-смещение в double-split (hi/lo float), иначе на `WORLD_LIMIT = 1e9` теряется точность float32.
2. **Прозрачность один раз на штрих — главный риск.** Canvas 2D композитит весь путь одной операцией: самопересечения не темнеют. В WebGL треугольники одного штриха перекрываются. Варианты: stencil «рисовать пиксель один раз» на штрих (stencil = id/инкремент, сброс между штрихами), или depth-трюк (свой depth на штрих, `LESS`), или отрисовка полупрозрачного штриха в offscreen FBO и композит с alpha. Непрозрачные штрихи (opacity = 1, большинство) — без этого.
3. **Порядок по seq:** рисовать в порядке seq; инкрементальная дорисовка поверх, как в тайлах. Батчинг соседних по seq штрихов с одинаковой кистью/непрозрачностью.
4. **Кеш:** сохранить идею тайлов как текстур (render-to-texture), чтобы pan оставался копированием; либо полная перерисовка из VBO каждый кадр, если GPU справляется — решить по замерам на iPhone.
5. **Отказоустойчивость:** `webglcontextlost`/`restored` → пересоздать буферы из сцены; нет WebGL2/ошибка шейдера/превышение памяти → `Canvas2DSceneRenderer`. Флаг принудительного выбора бэкенда для отладки (не в Storage публичных настроек).
6. **Тесты:** E2E сравнивают пиксели — для WebGL нужен допуск (сглаживание отличается, как уже между тайлами и прямым рендером), а не байтовое равенство; проверка в трёх движках, отдельно — реальные iPhone/iPad. Admin остаётся на Canvas 2D.

## Не делать

- Не переносить в WebGL хит-тест/ownership-логику и не смешивать GPU-код с `scene.ts`/`world.ts`.
- Не менять алгоритм spray/chisel (версионирование — `docs/brushes.md`): GPU-рендер обязан воспроизводить ту же геометрию.
