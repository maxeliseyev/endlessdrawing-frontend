# Кисти: косое перо и спрей

## Статус

`chisel` и `spray` работают в общем мире: backend принимает их (enum, миграция `0003_chisel_spray_brushes.sql`, bounds ниже), проверено совместным тестом `npm run test:integration`. Admin использует тот же renderer. При зуме вся effect-геометрия масштабируется целиком, случайный узор спрея от зума не зависит.

## Имена и поведение

| Wire value | Русский UI | English UI | Геометрия |
| --- | --- | --- | --- |
| `round` | Круглая кисть | Round brush | Canvas round caps / round joins |
| `square` | Квадратная кисть | Square brush | Canvas square caps / bevel joins |
| `chisel` | Косое перо | Chisel pen | Плоский прямоугольный каллиграфический наконечник под -45°, то есть `/` в экранных координатах |
| `spray` | Спрей | Spray | Детерминированный набор круглых частиц вдоль траектории |

Это формы кисти, не новые действия верхнего уровня: Кисть / Рука / Ластик остаются прежними. Все формы используют текущие цвет, width и opacity. Инструмент/форма восстанавливаются из существующих versioned preferences; старые round/square настройки остаются валидными.

## Косое перо

- `width` — длина наконечника, короткая сторона `max(1, width / 6)`.
- Угол фиксирован относительно мира: -45°; камера/направление движения/DPR его не меняют. Нажим и настройка угла сейчас не добавляются.
- Один клик — отпечаток повёрнутого прямоугольника.
- Между соседними точками прямоугольник протягивается непрерывно: выпуклая оболочка восьми углов двух отпечатков. Поэтому быстрый жест не оставляет разрывов между stamps.
- Полигоны имеют одинаковый winding, заполняются одним nonzero fill, включая пересечения и повороты. Opacity применяется один раз к целому штриху, не повторно на каждом сегменте.
- Hit-test использует ту же геометрию с допуском 4 CSS px, а не круглую аппроксимацию центральной линии.

## Спрей: алгоритм v1

Источник чистой геометрии — `src/brush-geometry.ts`; алгоритм является частью визуального контракта, его изменение требует согласования/версии, иначе старые штрихи изменят вид.

1. Seed — FNV-1a (uint32, Math.imul) от lowercase UUID штриха, генератор xorshift32. Если hash равен 0, начальное состояние `0x9e3779b9`. Выход `(state >>> 0) / 2^32`.
2. Stamps расположены по длине ломаной, а не по количеству pointer events или времени. Первая точка всегда даёт один burst. Номинальный шаг `max(1, width / 4)`.
3. Защита ресурсов: максимум 2048 stamps на штрих; для длинного пути шаг повышается до `max(1, width / 4, totalLength / 2047)`. Таким образом крайне длинный спрей становится разреженнее, но вычисления ограничены. Финальная неполная дистанция сама по себе не добавляет event-dependent stamp. Preview длинного жеста может перераспределяться при изменении общего шага; готовая запись воспроизводима.
4. Частиц на stamp: `min(48, max(6, ceil(width * 0.75)))`. Радиус частицы: `max(0.35, min(1.25, width / 20))`.
5. Для каждой частицы последовательно берутся два случайных числа: угол `2πu`, смещение `sqrt(v) * max(0, width / 2 - particleRadius)`. Равномерное распределение по диску; частицы целиком внутри диска диаметром width.
6. Все круги — отдельные замкнутые subpaths одного Path2D с одинаковым winding. Один fill с общей opacity. Внутри штриха перекрытия не затемняются повторно; разные штрихи композятся независимо как прежде.
7. Никаких `Math.random()`, таймеров, зависимости от DPR, камеры, порядка доставки или частоты кадров. Одинаковые UUID/width/points дают одну геометрию после preview/ack/snapshot/reload. Незначительные различия браузерного antialiasing возможны, побитовая идентичность растра между движками не обещается.
8. Ластик проверяет расстояние до реальных частиц (`radius + 4 CSS px`), не весь диск спрея. Аналитический hit-test избегает разного поведения Canvas stroke hit-test при допуске шире диаметра частицы.

Удержание неподвижного указателя не накапливает краску: нет временного flow/density, дополнительных серверных событий или pressure. Пустая траектория ничего не рисует. Один клик — один cloud. Максимум 98 304 частицы на один штрих; тяжёлые сцены требуют отдельного performance-профилирования перед публичным запуском.

Готовые effect Path2D кешируются в WeakMap, координаты относительны первой точке. Preview инвалидирует геометрию при append/decimation; готовые векторы считаются неизменяемыми. Камера/DPR не пересоздают случайный узор. При добавлении редактирования точек в будущем нужен явный geometry revision/инвалидация кеша.

## Backend-контракт (реализован)


- Добавить значения `chisel` и `spray` в brush enum, JSON/create validation, DB CHECK через миграцию, чтение/сериализацию публичных штрихов, fixtures и общий `docs/protocol.md`.
- Поля create остаются прежними: `id`, `points`, `brush`, `width`, `color`, `opacity`. Отдельных seed/particles/angle/density полей пока **нет**: seed выводится из UUID, геометрия восстанавливается клиентом. Цвет/ownership/seq остаются серверными по прежним правилам.
- Семантическая идемпотентность учитывает новые brush без замены геометрии; UUID и points должны сохраняться, а при повторе create не меняться.
- **Bounds chisel:** консервативно можно использовать имеющееся square-расширение `width / sqrt(2) + 1`. Более точный осевой запас для фиксированного наконечника: `(width + max(1, width / 6)) / (2 * sqrt(2)) + 1` по обеим осям.
- **Bounds spray:** имеющееся round-расширение `width / 2 + 1` включает все частицы. На краю мира не обрезать stroke bounds по геометрии.
- Проверить thick-stroke intersection на границе viewport, snapshot/reconnect, два браузера с одним UUID и взаимный порядок разных форм по seq.
- Публичные и admin-view renderer/hit-test должны использовать общие функции; нельзя рисовать chisel/spray как round в служебном интерфейсе.

## Проверки

Unit: валидация форм/Storage, геометрия и bounds наконечника, дубликаты/пустой путь, детерминизм UUID и fixed seed, инвариантность к абсолютным координатам и плотности collinear samples, размеры/ограничение числа частиц.

E2E: формы доступны в EN/RU, preview/Escape, совпадение preview и готового штриха, стабильный redraw после панорамирования, opacity/self-intersection и DPR 1/2, hit-test частиц/наконечника у границ мира, локальные undo/ластик, восстановление настроек. Эти тесты не заменяют ещё не выполненную серверную интеграцию новых brush.
