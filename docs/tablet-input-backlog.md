# Бэклог: планшеты, перо и touch

**Статус:** только задача в бэклоге, не реализация текущей итерации.

**Порядок:** отдельный этап после закрытой модерации (этап D).

**Первый целевой сценарий:** планшеты с активным пером. Полный мобильный UX/телефоны не входят в этот этап.

## Управление

- **Перо:** рисует выбранной кистью; нажим не меняет толщину/opacity. Палец при использовании пера перемещает камеру, не оставляет штрихи.
- **Без пера:** один палец использует выбранный инструмент (кисть рисует, рука перемещает, ластик удаляет целый свой подтверждённый штрих); два пальца панорамируют холст.
- **Появление второго пальца обязательно отменяет незавершённый штрих первого**, удаляет его preview и переводит жест в панорамирование. Ни линия, ни исходная одиночная точка не отправляются на сервер и не попадают в undo.
- После окончания двухпальцевого панорамирования оставшийся на экране палец не начинает новый штрих самопроизвольно. Для рисования нужен новый самостоятельный жест.
- **Долгое нажатие без движения:** открывает палитру у точки касания. При открытии отменяются незавершённый жест и начальная точка без отправки create. Движение сверх допуска/второй палец/перо/cancel отменяют таймер долгого нажатия.
- **Undo:** доступная кнопка внутри открытой палитры; использует тот же сессионный механизм удаления последнего подтверждённого штриха, что Ctrl/Cmd+Z. Никакой постоянной панели.
- Элементы палитры крупнее для пальцев, удобные интервалы и целевые области; палитра остаётся в границах экрана с учётом экранной клавиатуры и смены ориентации. Все новые подписи/ошибки — EN/RU.
- Нативное меню долгого нажатия и конфликтующие браузерные жесты подавляются **только на холсте**. Не запрещать штатные контекстные действия/редактирование в полях палитры и служебных формах.

## Инварианты и границы этапа

- **Без зума и чувствительности к нажатию.** Масштаб остаётся 1 world unit = 1 CSS px; pinch трактуется как панорамирование, не масштабирование. Геометрия и серверный порядок не зависят от типа указателя.
- Текущий desktop-ввод мышью/средней кнопкой/Space/wheel и клавиатурой не должен регрессировать.
- Нужна явная state machine активных pointerId и режима ввода; не считать `isPrimary` или один глобальный gesture достаточной моделью multi-touch.
- Способ распознавания «используется перо», продолжительность этого режима после потери pen proximity, приоритет одновременного пера/пальцев и поведение pen hover определить при реализации. Не угадывать наличие пера только по user-agent или одному `maxTouchPoints`.
- Длительность долгого нажатия, порог движения и минимальные touch targets выбрать и документировать при реализации; точные числа пока не утверждены.
- При palm rejection не превращать контакт ладони в штрих, случайное панорамирование или вызов палитры. **Проверять на настоящих устройствах**, поскольку браузерная эмуляция не воспроизводит аппаратное отсечение ладони и все последовательности событий.
- `pointercancel`, lost capture, уход приложения в фон, смена ориентации и прерывание ОС корректно сбрасывают жесты/таймеры. Неподтверждённый preview не становится сохранённой точкой.
- Не добавлять onboarding, баннеры, плавающую touch-панель или постоянные кнопки: обычное состояние по-прежнему только общий холст.

## Приёмка

- [ ] На реальном планшете перо рисует, палец при использовании пера панорамирует; ладонь не оставляет следов и не двигает камеру неожиданно.
- [ ] Без пера один палец работает выбранным инструментом, два пальца перемещают камеру без изменения масштаба.
- [ ] Второй палец во время preview отменяет весь штрих до отправки; ни локально, ни во втором независимом браузерном контексте не остаётся случайных линий/точек.
- [ ] Long press без движения открывает палитру и отменяет начальную точку. Движение/второй палец/pen/cancel отменяют long press. Закрытие палитры не завершает отменённый штрих.
- [ ] Окончание multi-touch не продолжает рисование оставшимся пальцем автоматически.
- [ ] Undo доступен только внутри вызванной палитры и работает с подтверждённым undo-стеком, включая reload и объекты вне viewport.
- [ ] Touch targets удобны на устройстве, меню не обрезается, поля остаются редактируемыми, EN/RU работают.
- [ ] Нативное long-press меню подавлено на холсте, но не глобально на странице/полях палитры.
- [ ] Проверены фон/cancel/capture/orientation, desktop-регрессии и отсутствие zoom/pressure.
- [ ] Зафиксированы реальные модели планшета/пера/ОС/браузера и результаты palm rejection; приоритетная проверка — iPad + Apple Pencil/Safari и планшет Windows + активное перо/Edge при наличии устройств. Не объявлять поддержку устройства по одному эмулированному тесту.
