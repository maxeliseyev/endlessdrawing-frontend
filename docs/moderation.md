# Закрытый вход администратора и модерация

## Статус и цель

Требование владельца: администратор должен иметь возможность убирать из общего мира рисунки, нарушающие закон или содержащие незаконную пропаганду. Обычные посетители не видят вход и инструменты модерации.

Это **обязательный этап перед публичным запуском**, не реализованная возможность текущего фронтенд-прототипа. Backend передал контракт реализации в работе: [`../endless-drawing-backend/docs/admin-api.md`](../../endless-drawing-backend/docs/admin-api.md). Это **единственный источник wire-форм**, правил cookie/CSRF, лимитов и ошибок; его раздел «Готовность» определяет проверенность API. Здесь остаются продуктовые и защитные требования, не второй независимый API-контракт. Соседний backend в рамках этой задачи не изменяется.

В `../endless-drawing-backend/docs/backend.md`, раздел 8, уже предусмотрен закрытый способ административного скрытия. Здесь уточняется требование владельца: нужен также браузерный вход и рабочий интерфейс администратора. Это единственное исключение из запрета дополнительных страниц: **служебный**, а не публичный продуктовый интерфейс.

## Невидимость для обычного посетителя

- Предлагаемый отдельный адрес: `https://endlessdrawing.com/admin/`, открываемый администратором вручную или из своей закладки.
- На публичном `/` нет ссылок, кнопок, скрытых DOM-элементов, горячих клавиш или пункта палитры «Администратор». Принцип «только общий холст» сохраняется.
- Не использовать `?admin=1`, localStorage-флаг, специальный session_secret или секретное сочетание клавиш для выдачи прав.
- Административный интерфейс — отдельная точка входа/сборочный entry, не импортируемый публичным приложением. Публичный холст не делает запросов проверки административной сессии и не загружает admin UI.
- Служебные страницы и ответы API: `Cache-Control: no-store`; страница входа: `noindex, nofollow`, без sitemap-ссылок. Это гигиена, не контроль доступа.
- **Скрытый URL не является защитой.** Адрес и JS могут стать известны любому. Любое чтение служебных данных и изменение мира проверяется сервером независимо от UI.

## Вход и безопасность

Схема по Admin API — отдельная серверная административная сессия, не анонимная сессия рисования:

1. Администратор открывает `/admin/`; при отсутствии действующей сессии видит только служебную форму входа. Она тоже поддерживает EN/RU по языку браузера.
2. Данные входа передаются только по HTTPS в POST body, без URL, телеметрии и логирования тела. Учётная запись создаётся закрытым серверным способом, публичной регистрации нет.
3. Согласованная схема: **логин + сложный пароль + обязательный WebAuthn passkey с user verification**. После проверки пароля сервер выдаёт только короткоживущий challenge второго фактора, а не полноценную административную сессию. Полные права появляются лишь после успешной проверки WebAuthn assertion. Пароль — сгенерированный менеджером паролей, минимум 20 символов; разрешить вставку/autofill, не полагаться на одни правила состава. На сервере хранится Argon2id hash с индивидуальной солью и настроенной стоимостью, не открытый пароль и не константа в JS. После обоих факторов backend создаёт ограниченную по времени, отзываемую сессию.
4. Сессия передаётся cookie `HttpOnly; Secure; SameSite=Strict`, host-only. Предлагаемое имя `__Host-ed-admin`, `Path=/`, без `Domain`. Никаких admin-токенов в localStorage/sessionStorage, VITE-переменных, URL или WS hello.
5. Все изменяющие административные запросы защищены от CSRF: проверка Origin и сессионный CSRF-токен в заголовке; SameSite — дополнительная защита, а не единственная. Проверки нужны и для входа/выхода с учётом их сценариев.
6. Rate limit входа и модерации, нейтральные ошибки авторизации, ограниченные payload и таймауты. API не возвращает stack trace/SQL/секреты. Защитить служебные страницы от framing, например `frame-ancestors 'none'`.
7. Явный выход отзывает сессию на сервере. Idle и absolute expiry, отзыв после смены данных входа, повторная проверка прав при каждом запросе обязательны; конкретные сроки согласовать.
8. `401` закрывает доступ к инструментам и возвращает форму входа без автоматического повтора удаления после нового входа. `403` не обходится клиентом.
9. По решению владельца допускаются обычные WebAuthn passkeys с `userVerification: required`, включая Touch ID и синхронизируемые/platform credentials. Аттестация устройства и CA trust store не нужны; в Admin API policy — `passkey_uv`. Password-only fallback не допускается; admin включается явно с HTTPS RP/origin. Pre-auth cookie не выдаёт прав, CSRF хранится только в памяти admin entry. Каждый verify attempt потребляет challenge; после ошибки/отмены нужен новый password → challenge, не повтор assertion.

Административная cookie **не меняет** авторизацию обычного `stroke.delete` и `own` в публичном `/ws`. Даже администратор использует отдельную серверную операцию скрытия, а не обход проверки владельца в пользовательском API.

## Ключ вместо SSH: WebAuthn/FIDO2

Браузер не использует `~/.ssh` и не должен просить загрузить приватный SSH-ключ. Нативный браузерный механизм — WebAuthn через `navigator.credentials.create()` / `navigator.credentials.get()` на HTTPS. Владелец выбрал passkeys через Touch ID; platform/synced credentials разрешены, аппаратный ключ не обязателен. Сервер получает доказательство user verification, не биометрию и не гарантию именно отпечатка: ОС может предложить другую системную проверку. Основной и резервный credentials нужны отдельно; один iCloud credential на нескольких устройствах не считать двумя независимыми регистрациями.

- Для каждого администратора зарегистрировать основной и запасной ключ; запасной хранить отдельно. Второй фактор обязателен, password-only обхода нет.
- Сайт получает credential ID и публичный ключ, приватный ключ сайту не передаётся. Аппаратный ключ выполняет подпись внутри устройства. Синхронизируемые passkeys могут храниться/синхронизироваться у провайдера — не обещать им свойства неэкспортируемого аппаратного ключа.
- Сервер выдаёт криптографически случайные одноразовые challenge с коротким TTL, привязанные к попытке входа, аккаунту и назначению операции. Проверяет подпись, ожидаемые origin и RP ID, challenge, user presence/verification согласно политике, включая `userVerification: required`. Challenge повторно не принимается, неуспешная или прерванная церемония не открывает сессию.
- RP ID и точный origin согласовать для production `https://endlessdrawing.com`; localhost/dev — отдельная конфигурация и отдельные тестовые credentials. Не ослаблять production origin-проверку ради разработки.
- Регистрация/удаление ключей — только закрытый provisioning или уже аутентифицированный администратор с повторным подтверждением факторов, не публичный endpoint по знанию логина. Не выдавать право регистрации нового ключа после одного пароля.
- Потеря всех ключей: заранее описанная закрытая серверная процедура восстановления с проверкой личности владельца и отзывом прежних credentials/сессий. Не вводить скрытый универсальный пароль, секрет в URL или обход MFA через фронтенд. Восстановление и изменение факторов аудируются.
- Отсутствие WebAuthn/подходящего ключа, отмена системного диалога или ошибка проверки дают понятную локализованную ошибку, но не fallback к password-only.
- Использовать поддерживаемую серверную WebAuthn-библиотеку, не писать проверку криптографии самостоятельно. Не объявлять конкретную модель ключа гарантированно поддерживаемой без совместного браузерного теста.

## Рабочий сценарий модератора

- После входа открывается служебное представление того же общего мира: панорамирование, выбор штриха под курсором, возможность набрать выделение из нескольких штрихов. Публичные режимы рисования не должны случайно запускать административное удаление.
- «Рисунок» сейчас не отдельная сущность: данные состоят из штрихов. Один объект может состоять из десятков штрихов; поэтому нужны одиночный и множественный выбор. Выделение прямоугольником допустимо только с предварительным просмотром попавших штрихов: нельзя молча удалять всё содержимое bbox вместе с соседними работами.
- Выбранные объекты явно подсвечиваются только в служебном интерфейсе. Перед отправкой показать число и UUID, запросить причину и подтверждение действия. Escape отменяет выделение/подтверждение, ничего не отправляя.
- У администратора есть право скрывать любые штрихи независимо от `own`, но оно проверяется сервером на каждом UUID.
- Скрытие — soft delete/tombstone на сервере, не рисование белым и не локальное удаление из Canvas. Публичное undo автора не может восстановить скрытый штрих; повтор create того же UUID не воскрешает его.
- Операция проходит через тот же последовательный обработчик мутаций, что и публичные create/delete, и только после commit рассылает обычное `stroke.deleted` всем подписчикам исходной области. Публичные события не раскрывают администратора и причину.
- Новый snapshot не содержит скрытые штрихи. При reconnect устаревший кеш заменяется; скрытые объекты не возвращаются.
- Подтверждение действия показывается только после ответа сервера. Ошибка/потеря ответа не доказывает результат: нужно безопасное повторение по идентификатору операции либо проверка состояния, без ложного «удалено».
- По Admin API batch атомарный, максимум 100 различных UUID. Неизвестный UUID отклоняет всю группу; уже удалённые возвращаются отдельно. Причина непустая после trim, не более 1000 Unicode chars / 4000 UTF-8 bytes. После потери ответа проверять operation или повторять тот же operation_id/payload; после нового входа не отправлять скрытие автоматически.

## Источник API и последовательность реализации

Использовать только [`admin-api.md` в backend](../../endless-drawing-backend/docs/admin-api.md): session → login/options → login → browser WebAuthn → login/verify; logout, hide и проверка operation — по его точным формам. Все fetch с `credentials: 'same-origin'`, изменяющие запросы — JSON + `X-CSRF-Token`. Не сериализовать credential одним `JSON.stringify`: нужны base64url adapters для buffer-полей и extensions согласно серверным fixtures.

Просмотр мира в служебном режиме — обычный WS v1 с отдельным случайным анонимным drawing secret, не административным токеном. Публичные рисование/ластик отключены, `own` не подменяется; скрытие только через административный HTTP API.

Enrollment — закрытый сценарий из того же контракта: аккаунт и одноразовый token создаются серверным CLI по SSH, затем две регистрации через браузер. Если UI enrollment не реализован, явно считать production provisioning заблокированным, а не обещать вход с незарегистрированными ключами. `complete:true` не выдаёт сессию: после него новый обычный вход.

Пока можно делать отдельный entry, typed client, adapters и mock-тесты. Реальные fixtures, готовность backend, Touch ID и резервного passkey проверяются совместно; одна успешная mock-авторизация не означает готовую интеграцию.

## Аудит и политика

В закрытом серверном журнале хранить идентификатор администратора, время, UUID скрытых штрихов, причину, идентификатор операции и результат. Не записывать пароль, cookie, сессионные секреты и исходные тела запросов. Права чтения аудита ограничить. Повтор операции не должен давать ложные новые удаления.

Решение о нарушении принимает уполномоченный администратор по утверждённым правилам, а не фронтенд по произвольному списку запрещённых тем. Юрисдикцию, правила модерации, сроки хранения tombstone/аудита/исходной геометрии и резервных копий утверждает владелец до запуска. Soft delete убирает из публичного мира, но сам по себе не означает физическое удаление из БД/backup. Не обещать бесконечное хранение запрещённого материала или юридическое соответствие одной кнопкой удаления.

## Приёмка

- [ ] На публичном холсте и в палитре нет входа/инструментов администратора; штатный пользователь может удалить только свои штрихи.
- [ ] Прямой запрос к API без сессии/с просроченной сессией отклоняется сервером. Подмена UI, Storage, `own`, query и полей WS не выдаёт права.
- [ ] Ошибочные данные входа, brute force, CSRF и попытка framing не дают доступ; logout/истечение/отзыв блокируют дальнейшие действия.
- [ ] Один верный пароль без FIDO2-подтверждения не открывает административную сессию. Неверные origin/RP ID, подпись, challenge, replay, истёкший challenge, недостаточная user verification и отмена диалога отклоняются.
- [ ] Проверены основной/запасной ключ, закрытая регистрация/отзыв credentials и процедура восстановления без password-only обхода; учётные данные и админ-сессии не утекают в frontend Storage/логи.
- [ ] Администратор видит выбранные штрихи, подтверждает действие и причину; отмена не изменяет мир. Вход/ошибки/подписи работают в EN/RU.
- [ ] Скрытие чужого рисунка из нескольких штрихов убирает его в двух независимых публичных браузерных контекстах без reload; соседние невыбранные штрихи сохраняются.
- [ ] Повтор скрытия безопасен, create старого UUID и undo автора не восстанавливают объект; новый snapshot/reload не возвращает скрытый рисунок.
- [ ] Скрытие во время snapshot/reconnect не теряется; временная ошибка и атомарный отказ batch отражаются честно.
- [ ] В публичной сборке/Storage/URL/логах нет административных данных входа; в публичных событиях нет причины/служебного аудита.
- [ ] В журнале есть актор/время/UUID/причина/результат, публичные посетители не имеют к нему доступа.
- [ ] Согласованы API, параметры WebAuthn/provisioning/recovery, лимиты, деплой служебного entry, политика и эксплуатационные инструкции.
